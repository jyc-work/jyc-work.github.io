## 重复请求不一定是客户端 Bug

同一次业务动作可能由于网络超时、用户重复点击、网关重试或消费者重投而被服务端接收多次。即使前端禁用了按钮，后端仍需要独立验证请求是否已被处理。

## 幂等键和唯一约束

一个常见实现是为每次业务意图生成稳定键，并在数据库中约束唯一性。第二次收到相同键时，返回之前的结果或适当状态，而不是再次执行副作用。

设计时尤其要注意：同一个键如果携带了**不同的业务参数**，应拒绝冲突请求，而不是静默复用旧结果。

## 事务边界

本地事务可以保证多项数据库操作原子提交，却不能自动把第三方 HTTP 接口变成同一个事务的一部分。

对外部服务写入，需要考虑可靠消息、Outbox、对账或补偿方案，具体取决于能否控制对方的幂等行为。

## 建议测试集

- 两个并发请求携带相同幂等键。
- 已成功提交后客户端超时并重试。
- 相同键对应不同参数。
- 外部接口成功、本地落库失败。
- 记录过期后再次收到旧请求。

验收时应断言数据库最终状态与外部调用次数，而不只是判断 HTTP 返回码。
